# VerifyAfrica API

VerifyAfrica provides identity verification, compliance screening, and government registry checks across Africa. Use a single API to verify documents, screen for AML risk, validate addresses, and query official registries in Nigeria, Ghana, Kenya, South Africa, and more.

## Base URL

```
https://api.verifyafrica.io
```

## Authentication

Include your tenant API key as a Bearer token on every request:

```
Authorization: Bearer VA-your_api_key_here
```

Do not send `X-API-KEY`. The API key identifies the tenant — no `X-TENANT-ID` header is required.

## Core Endpoints

| Endpoint | Description |
| --- | --- |
| `POST /api/v2/public/verifications/requests/document_verification/` | Document verification |
| `POST /api/v2/public/verifications/requests/facial_screening/` | Facial screening |
| `POST /api/v2/public/verifications/requests/address_verification/` | Address verification |
| `POST /api/v2/public/verifications/requests/aml_screening/` | AML screening |
| `POST /api/v2/public/verifications/requests/business_aml_screening/` | Business AML screening |
| `POST /api/v2/public/verifications/requests/kyb/` | KYB (know your business) |
| `POST /api/v2/public/verifications/requests/crypto_wallet_screening/` | Crypto wallet screening |
| `POST /api/v2/public/verifications/requests/risk_assessment/` | Risk assessment |
| `POST /api/v2/public/verifications/requests/government_registry_checks/` | Government registry checks (include `verification_type` in body) |
| `GET /api/v2/public/verifications/requests/?verification_id={verification_id}` | Retrieve verification status and details |

Product paths lock the check for single-type products. For `government_registry_checks`, send `verification_type` in the body (e.g. `ng_bvn_verification`). Public creates always use **direct (offsite)** mode and return immediately with `PENDING` — use [Webhooks](/webhooks) or the GET endpoint for the final result.

## Webhooks

Receive `verification.completed` or `verification.failed` events at your own HTTPS endpoint when a verification reaches a **terminal** status (`SUCCESS`, `FAILED`, or `ERROR`).

Public API creates return immediately with `PENDING` — do not wait on the create response for the final result. Configure the webhook URL and optional auth token in the dashboard **API Keys** page.

See the [Webhooks](/webhooks) guide for payload shape, authentication, response requirements, and automatic retries.

## Public response rules

Create, GET, and webhook payloads share the same public shape:

- **Provider-agnostic** — internal provider names and hosted provider URLs are never exposed
- **Proofs are HTTPS URLs** — send `document.proof` / `face.proof` as `https://…` links (base64 data URIs are rejected)
- **`input_data` proofs** — returned as the same URLs you submitted at create time
- **`proofs` / `proofs_available`** — echo those original URLs on GET and webhooks
- **`response_data`** — verification result only; access tokens, provider proof links, and similar upstream artifacts are stripped

## Response format

Success (create accepts the request and starts processing):

```json
{
  "success": true,
  "message": "Verification request accepted. Processing has started; you will be notified via webhook when complete.",
  "data": {
    "id": "…",
    "status": "PENDING",
    "response_data": {},
    "proofs": {},
    "proofs_available": false
  }
}
```

## Example Error Responses

All public API errors use the same envelope:

```json
{
  "success": false,
  "message": "…",
  "errors": ["…"]
}
```

### 400 Bad Request

```json
{
  "success": false,
  "message": "Missing required parameters for 'ng_bvn_verification': bvn",
  "errors": ["Missing required parameters for 'ng_bvn_verification': bvn"]
}
```

### 401 Unauthorized

```json
{
  "success": false,
  "message": "Invalid API key.",
  "errors": ["Invalid API key."]
}
```

### 403 Forbidden

```json
{
  "success": false,
  "message": "Tenant KYC is not complete. Please complete KYC before creating team members or performing verifications.",
  "errors": [
    "Tenant KYC is not complete. Please complete KYC before creating team members or performing verifications."
  ]
}
```

### 404 Not Found

```json
{
  "success": false,
  "message": "Resource not found.",
  "errors": ["Resource not found."]
}
```

### 500 Internal Server Error

```json
{
  "success": false,
  "message": "An unexpected error occurred.",
  "errors": ["An unexpected error occurred."]
}
```


## Verification Categories

Explore the **Endpoints** section in the sidebar for detailed guides on each verification type:

- **Identity Verification** — Document and facial screening
- **Compliance & Screening** — AML, business AML, and KYB checks
- **Address Verification** — Physical address validation
- **Risk & Crypto** — Fraud risk scoring and crypto wallet screening
- **Government Registry Checks** — Official ID and registry lookups by country

For the full list of webhook `event` names and `verification_type` values, see the OpenAPI schemas in the [Webhooks API reference](/api/webhooks) (`WebhookEvent`, `PublicVerificationType`, `VerificationStatus`).

## Quick Example

```bash
curl -X POST https://api.verifyafrica.io/api/v2/public/verifications/requests/government_registry_checks/ \
  -H "Authorization: Bearer VA-your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "verification_type": "ng_bvn_verification",
    "input_data": {
      "bvn": "22222222222",
      "first_name": "John",
      "last_name": "Doe"
    }
  }'
```
