# Facial Screening

Run liveness / face match in either **link** or **direct** mode.

| Mode | What you send | What create returns | When verification finishes |
| --- | --- | --- | --- |
| `link` (default) | `input_data` only — no face image | `data.link.url` for the customer | After the customer completes capture on the hosted page |
| `direct` | HTTPS face proof URL in `input_data` | Accepted request (`PENDING`) | After provider processing completes |

Use [Webhooks](/webhooks) or `GET …/requests/?verification_id=…` for the terminal result in both modes.

In the field tables below:

- **Required** — must be sent for that mode
- **Optional** — accepted for that mode
- **—** — not used in that mode (omit it)

:::tip API Reference
Jump directly to the interactive API docs:

- [API reference](/api) — schemas, examples, and playground
- Create: `POST /api/v2/public/verifications/requests/facial_screening/`
- Detail: `GET /api/v2/public/verifications/requests/?verification_id={verification_id}`
:::

## Verification Type

```
face_match
```

## Use Cases

- Confirm the person presenting is a live person
- Detect presentation attacks with liveness checks
- Hosted capture in your onboarding flow (`link`)
- Verify a selfie you already collected (`direct`)

## Choosing a mode

Send top-level `mode`:

- **`link`** — `input_data` only. Response includes `data.link.url`. Optional `send_email` / `allow_file_upload`. Do **not** send `face.proof`.
- **`direct`** — Send `face.proof` as an HTTPS URL. Verification starts in the background. Do **not** send `send_email`, `allow_file_upload`, or `ttl`.

If `mode` is omitted, it defaults to `link`. Do not send internal `method_type`.

## Required fields at a glance

### Link mode (`mode: "link"` or omitted)

| Field | Required? | Notes |
| --- | --- | --- |
| `input_data` | **Yes** | Customer and face capture options |
| `input_data.face` | **Yes** | Capture settings (no proof URL) |
| `input_data.email` | When `send_email: true` | Required to deliver the hosted link by email |
| `send_email` | No | Link only — defaults to `false` |
| `allow_file_upload` | No | Link only — overrides tenant camera vs file-upload setting |

**Do not send in link mode:** `input_data.face.proof`

### Direct mode (`mode: "direct"`)

| Field | Required? | Notes |
| --- | --- | --- |
| `input_data` | **Yes** | Customer and face proof |
| `input_data.face` | **Yes** | Must include `proof` |
| `input_data.face.proof` | **Yes** | HTTPS URL of the selfie / face image |
| `input_data.email` | No | Optional identifier |

**Do not send in direct mode:** `send_email`, `allow_file_upload`, `input_data.ttl`, `input_data.allow_file_upload`

## Request body

| Parameter | Type | Link | Direct | Description |
| --- | --- | --- | --- | --- |
| `mode` | string | Optional (default `link`) | Optional | `"link"` or `"direct"`. |
| `input_data` | object | Required | Required | Customer and face options. |
| `send_email` | boolean | Optional (default `false`) | — | `true` to email the hosted link to `input_data.email`. |
| `allow_file_upload` | boolean | Optional (tenant default `true`) | — | Overrides the tenant product setting. `true` = camera + file upload; `false` = camera only. |

### `input_data`

| Parameter | Type | Link | Direct | Description |
| --- | --- | --- | --- | --- |
| `email` | string | Required when `send_email` is true; otherwise optional | Optional | Customer's email. Required when `send_email: true`. |
| `language` | string | Optional (default `"EN"`) | Optional (default `"EN"`) | Language code (e.g. `"EN"`, `"FR"`). |
| `ttl` | integer | Optional (default `60`) | — | Link lifetime in minutes. One of `15`, `30`, `60`, `120`, `240`. |
| `country` | string | Optional | Optional | ISO 3166-1 alpha-2 country code. |
| `allow_file_upload` | boolean | Optional | — | Same override as the top-level field. |
| `face` | object | Required | Required | Face capture / proof options. |

### `input_data.face`

| Parameter | Type | Link | Direct | Description |
| --- | --- | --- | --- | --- |
| `proof` | string (URL) | — | Required | HTTPS URL of the face image / selfie. Base64 data URIs are rejected. |
| `verification_mode` | string | Optional (default `"any"`) | Optional (default `"any"`) | `"any"`, `"image_only"`, or `"video_only"`. |
| `check_duplicate_request` | boolean | Optional (default `false`) | Optional (default `false`) | `true` to flag duplicate faces. |

Do not send `allow_online` or `allow_offline`.

## Link mode example

**Endpoint:** `POST https://api.verifyafrica.io/api/v2/public/verifications/requests/facial_screening/`

```json
{
  "mode": "link",
  "send_email": false,
  "allow_file_upload": true,
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "ttl": 60,
    "face": {
      "verification_mode": "any",
      "check_duplicate_request": false
    }
  }
}
```

Create returns `status: PENDING` and `data.link.url`. Redirect the customer.

## Direct mode example

```json
{
  "mode": "direct",
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "face": {
      "proof": "https://cdn.example.com/selfie.jpg",
      "verification_mode": "any",
      "check_duplicate_request": false
    }
  }
}
```

Create returns `status: PENDING` while verification runs. No capture `link`. Use webhooks or GET for the terminal result.

## Example Error Responses

Errors use the v2 envelope `{ "success": false, "message": "…", "errors": ["…"] }`.

```json
{
  "success": false,
  "message": "Invalid API key.",
  "errors": ["Invalid API key."]
}
```
