# Facial Screening

Perform real-time liveness detection and face match verification against a reference document.

:::tip API Reference
Jump directly to the interactive API docs:

- [API reference](/api) — schemas, examples, and playground
- Create: `POST /api/v2/public/verifications/requests/facial_screening/`
- Detail: `GET /api/v2/public/verifications/requests/?verification_id={verification_id}`
:::

## Verification Type

```
face_match
```

## Use Cases

- Confirm the person presenting an ID is the document holder
- Detect presentation attacks with liveness checks
- Combine with document verification for stronger KYC

## Input Parameters

Pass these fields inside `input_data` in your request body.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `face` | object | Yes | Face image and verification options. See nested fields below. |
| `email` | string | No | Customer's email address. |
| `language` | string | No | Language code (e.g. `"EN"`, `"FR"`). Defaults to `"EN"`. |
| `country` | string | No | ISO 3166-1 alpha-2 country code (e.g. `"NG"`, `"ZA"`, `"GH"`, `"KE"`). |

### `face` object

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `proof` | string | Yes | HTTPS URL to the face image (`jpeg`/`jpg`/`png`). Base64 data URIs are **not** accepted on the public API. |
| `verification_mode` | string | Yes | Capture type. One of: `"any"`, `"image_only"`, `"video_only"`. |
| `check_duplicate_request` | boolean | No | `true` to flag duplicate faces, `false` to allow. Defaults to `false`. |

## Making a Request

Public API creates always use **direct (offsite)** mode. Do not send `method_type` — the API forces `offsite`.

The create response returns immediately with `status: PENDING`. Use [Webhooks](/webhooks) or the GET detail endpoint for the final result. GET and webhook payloads echo your original `face.proof` URL in both `input_data` and top-level `proofs`.

**Endpoint:** `POST https://api.verifyafrica.io/api/v2/public/verifications/requests/facial_screening/`

Authenticate with `Authorization: Bearer <VA-…api-key>`. The product path selects the verification type — do not send `verification_type`.

```json
{
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "face": {
      "proof": "https://cdn.example.com/faces/selfie.jpg",
      "verification_mode": "any",
      "check_duplicate_request": false
    }
  }
}
```


## Example Error Responses

Errors use the v2 envelope `{ "success": false, "message": "…", "errors": ["…"] }`.

```json
{
  "success": false,
  "message": "Invalid API key.",
  "errors": ["Invalid API key."]
}
```

```json
{

  "message": "Missing required parameters for 'face_match': …",
  "errors": ["Missing required parameters for 'face_match': …"]
}
```
