# Government Registry Checks

Verify identity and registry records against official government databases across Côte d'Ivoire, Ghana, Kenya, Nigeria, South Africa, and the United States.

**Direct mode** is always available. **Link mode** is only available for checks that support Korapay facial matching, and only when you set `input_data.require_selfie` to `true` so the customer can capture a selfie on the hosted page.

| Mode | When you can use it | What you send | What create returns |
| --- | --- | --- | --- |
| `direct` | Every registry check | Identifier (+ optional validation / selfie URL) | Accepted request (`PENDING`) |
| `link` | Selfie-capable checks **and** `require_selfie: true` | Email + optional prefills (no selfie URL) | `data.link.url` for selfie capture |

Use [Webhooks](/webhooks) (`kr.verification.completed` / `kr.verification.failed`) or `GET …/requests/?verification_id=…` for the terminal result in both modes.

Billing for registry checks is deferred until the check is submitted to Korapay (not at HTTP create).

Jump directly to the interactive API docs:

- [API reference](/api) — schemas, examples, and playground
- Create: `POST /api/v2/public/verifications/requests/government_registry_checks/`

## Getting Started

All checks share one product endpoint. Set `verification_type` to the check you need (for example `ng_nin_verification`):

`POST /api/v2/public/verifications/requests/government_registry_checks/`

Browse a country below, then open the check page for its `input_data` fields.

## Choosing a mode

Send top-level `mode`. Do not send internal `method_type`.

- **`direct`** — Run immediately with the identifier you supply. Optional name / DOB validation and optional `selfie` HTTPS URL (selfie-capable types only). Do **not** send `send_email`, `allow_file_upload`, `ttl`, or `require_selfie`.
- **`link`** — Hosted VerifyAfrica page for **selfie capture**. Allowed only when the check supports facial matching **and** `input_data.require_selfie` is `true`. Prefill registry fields to lock them; omit fields so the customer enters them. Response includes `data.link.url`. Do **not** send a selfie proof URL.

If `mode` is omitted:

- it becomes `link` when the check supports selfie **and** `input_data.require_selfie` is `true`
- otherwise it becomes `direct`

Sending `mode: "link"` without `require_selfie: true`, or on a check that does not support selfie matching, returns **400**.

### Checks that support selfie (link mode allowed)

These match Korapay Identity facial matching (`validation.selfie`):

| Country | Checks |
| --- | --- |
| Nigeria | BVN, NIN, Virtual NIN, Advanced phone verification |
| Ghana | Passport, Voter card, SSNIT, Driver's licence |
| Kenya | Passport, National ID |
| Côte d'Ivoire | National ID, Residence card |

### Checks that are direct-only (no selfie)

Nigeria phone lookup, CAC, Nigeria passport · Kenya phone lookup, Tax PIN · South Africa ID · United States SSN

Sending `input_data.selfie` or `input_data.require_selfie: true` on these checks returns **400**.

## Required fields at a glance

### Link mode (`mode: "link"`)

Link mode is **not** the default. It is rejected unless the check supports selfie matching and `input_data.require_selfie` is `true`.

| Field | Required? | Notes |
| --- | --- | --- |
| `verification_type` | **Yes** | Must be a selfie-capable check (see table above) |
| `input_data` | **Yes** | Customer email and optional prefills |
| `input_data.email` | **Yes** | Used for the hosted session / notifications |
| `input_data.require_selfie` | **Yes** | Must be `true` |
| Primary identifier (e.g. `nin`) | No | Prefill to lock it; omit so the customer enters it |
| Name / DOB validation fields | No | Prefill to lock; omit so the customer enters them |
| `send_email` | No | Emails `data.link.url` to `input_data.email` |
| `allow_file_upload` | No | Camera + upload vs camera only |
| `input_data.ttl` | No | Link lifetime in minutes (`15`, `30`, `60`, `120`, `240`, `1440`) |

**Do not send in link mode:** `input_data.selfie` (proof URL)

### Direct mode (`mode: "direct"`)

| Field | Required? | Notes |
| --- | --- | --- |
| `verification_type` | **Yes** | e.g. `ng_nin_verification` |
| `input_data` | **Yes** | Identifier and optional validation |
| Primary identifier (e.g. `nin`) | **Yes** | Required for that check type |
| Name / DOB validation fields | No | Compared against the registry response when present. **Required** for [US SSN](./us-ssn-verification) (plus `phone_number`) |
| `input_data.selfie` | No | HTTPS URL of a selfie image (selfie-capable types only) |

**Do not send in direct mode:** `send_email`, `allow_file_upload`, `input_data.ttl`, `input_data.require_selfie`

## Request body

| Parameter | Type | Link | Direct | Description |
| --- | --- | --- | --- | --- |
| `mode` | string | Optional | Optional (default `direct` unless `require_selfie` is true) | `"link"` or `"direct"`. Link only for selfie-capable checks with `require_selfie: true`. |
| `verification_type` | string | Required | Required | Registry check type (see country pages). |
| `input_data` | object | Required | Required | Identifier, email (link), optional validation / selfie. |
| `send_email` | boolean | Optional (default `false`) | — | `true` to email the hosted link. |
| `allow_file_upload` | boolean | Optional (tenant default `true`) | — | Selfie-capable types only. `true` = camera + file upload; `false` = camera only. |

### Shared `input_data` options

| Parameter | Type | Link | Direct | Description |
| --- | --- | --- | --- | --- |
| `email` | string | Required | Optional | Customer email (required for link). |
| `language` | string | Optional (default `"EN"`) | Optional | Language code. |
| `ttl` | integer | Optional (default `60`) | — | Link lifetime in minutes. |
| `require_selfie` | boolean | **Required** (`true`) | — | Must be `true` to use link mode. |
| `allow_file_upload` | boolean | Optional | — | Same override as the top-level field. |
| `selfie` | string (URL) | — | Optional | HTTPS selfie image URL for facial matching when supported. |
| `first_name` / `last_name` / `date_of_birth` | string | Optional | Optional | Validation fields when the check supports them. Prefills lock on link mode. |

Each check’s required identifier and optional fields are listed on its endpoint page (for example [Nigeria NIN](./ng-nin-verification)).

## Example — link mode (NIN)

```json
{
  "verification_type": "ng_nin_verification",
  "mode": "link",
  "send_email": true,
  "allow_file_upload": true,
  "input_data": {
    "email": "customer@example.com",
    "ttl": 60,
    "nin": "55555555555",
    "require_selfie": true
  }
}
```

Response includes `data.link.url`. The customer captures a selfie (and any fields you omitted) on the hosted page.

## Example — direct mode (NIN)

```json
{
  "verification_type": "ng_nin_verification",
  "mode": "direct",
  "input_data": {
    "nin": "55555555555",
    "first_name": "Bimbo",
    "last_name": "Olakunle",
    "date_of_birth": "1988-04-04"
  }
}
```

Create returns `PENDING`. Listen for `kr.verification.completed` / `kr.verification.failed`, or poll GET detail.

## Sandbox testing (required on test)

When your VerifyAfrica environment uses Korapay **test** credentials (sandbox / test dashboard), you **must** use the official Korapay sandbox identity values below. Real government IDs (real NIN, BVN, passport, etc.) return “data not found” / fail on test.

Source: [Korapay — Testing your Integration](https://developers.korapay.com/docs/testing-your-integration) (Identity section). Also see [KYC Nigeria](https://developers.korapay.com/docs/kyc-nigeria) for Nigeria product context.

- Put the value in the check’s primary `input_data` field (column **Request key**).
- Use the **Valid** row for a successful match; use **Invalid** to exercise failure paths.
- Live / production credentials require real IDs — sandbox values will not work there.
