:::tip Test vs production
On **test**, identity values are sandbox-specific — you must use the sandbox IDs listed in these docs. Real government IDs fail on test.

On **production**, you can use any real government ID. Sandbox values do not work with live credentials.
:::

Official government registry checks for the United States.

## API Reference

- [Country operations](/api/single-gov-united-states)

All checks in this country use the same product endpoint:

`POST /api/v2/public/verifications/requests/government_registry_checks/`

Set `verification_type` to the identifier for the check you need. Retrieve results with `GET /api/v2/public/verifications/requests/?verification_id={verification_id}`.

Every check supports **link** and **direct** mode. See [Government Registry Checks](../government-registry) for shared `mode`, billing, and webhook details.

SSN verification requires the holder's first name, last name, date of birth, and US phone number alongside the SSN. Processing runs it asynchronously.

## Sandbox testing (required on test)

On the **test** environment you must use sandbox identity values Real SSNs fail on test.

| Check | `verification_type` | Request keys | Valid sandbox values |
| --- | --- | --- | --- |
| [SSN](../../us-ssn-verification) | `us_ssn_verification` | `ssn`, `first_name`, `last_name`, `phone_number`, `date_of_birth` | `765439022`, `John`, `Smith`, `+12109041086`, `1995-01-23` |

Full GRC sandbox tables: [Government Registry Checks](../government-registry#sandbox-testing-required-on-test).
