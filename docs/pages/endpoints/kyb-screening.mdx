# KYB - Know Your Business

KYB supports three bases. Set `input_data.kyb.base` to choose one. Link and direct modes both work for every base. The backend stores Shufti coverage per jurisdiction and rejects unsupported identifiers, document labels, and purchase documents. Fields that do not belong to the selected base are stripped before the provider request.

| Base | What it does |
| --- | --- |
| `search` (default) | Enhanced registry lookup |
| `document` | Customer or merchant supplies a supported business document |
| `document_purchase` | Retrieve official registry documents. Results arrive on your tenant webhook — do not send `callback_url` |

| Mode | What you send | What create returns | When verification finishes |
| --- | --- | --- | --- |
| `link` (default) | Email plus optional locks | `data.link.url` | After the customer completes the hosted form |
| `direct` | Base-specific company fields | Accepted request (`PENDING`) | After Shufti finishes (webhook) |

Coverage: `GET /api/v2/public/verifications/supported-countries/?verification_type=kyb_screening&kyb_base=search`

Use [Webhooks](/webhooks) for `verification.completed` / `verification.failed`.

## Verification Type

```
kyb_screening
```

## `input_data.kyb`

| Parameter | Bases | Description |
| --- | --- | --- |
| `base` | all | `search`, `document`, or `document_purchase`. Defaults to `search`. |
| `advanced_search` | search | `"1"` / `"0"`. Defaults to `"1"`. |
| `company_name` | search | Used when the jurisdiction supports `company_name`. |
| `company_registration_number` | search, document_purchase | Registration / RC number. |
| `company_jurisdiction_code` | search, document_purchase | Jurisdiction code. US states use `US_AL`. Purchase is sent to Shufti as a lowercase ISO code. |
| `search_type` | search | `fuzzy` (default), `contains`, or `start_with`. |
| `search_by` | search | Must be a coverage identifier for that country (`vat_number`, `trn_number`, …). |
| `search_word` | search | Value for `search_by` when it is not company name or registration number. |
| `ai_business_insights` | search | Optional `"1"` / `"0"`. |
| `document_proof` | document | HTTPS URL of the business document. |
| `additional_proof_labels` | document | Labels from document coverage for that country. |
| `validate_document` | document | `"1"` requires exactly one proof. |
| `required_documents` | document_purchase | Payload names from purchase coverage. Empty means all supported documents. |

`callback_url` is injected server-side. Do not send it.

## Direct search example

```json
{
  "mode": "direct",
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "country": "NG",
    "kyb": {
      "base": "search",
      "company_name": "Acme Limited",
      "company_registration_number": "RC123456",
      "company_jurisdiction_code": "NG",
      "search_type": "fuzzy",
      "advanced_search": true
    }
  }
}
```

Saudi VAT search uses `search_by` / `search_word` because `vat_number` is a coverage identifier for that country. Egypt only supports `company_name`.

## Link mode example

```json
{
  "mode": "link",
  "send_email": false,
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "ttl": 60,
    "country": "NG",
    "kyb": {
      "base": "search"
    }
  }
}
```

## Direct document example

```json
{
  "mode": "direct",
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "country": "NG",
    "kyb": {
      "base": "document",
      "document_proof": "https://files.example.com/cac-certificate.pdf",
      "additional_proof_labels": ["certificate_of_incorporation"],
      "validate_document": "1"
    }
  }
}
```

## Direct document purchase example

```json
{
  "mode": "direct",
  "input_data": {
    "email": "customer@example.com",
    "language": "EN",
    "country": "NG",
    "kyb": {
      "base": "document_purchase",
      "company_registration_number": "RC123456",
      "company_jurisdiction_code": "NG",
      "required_documents": []
    }
  }
}
```
