# Crypto Wallet Screening

Screen cryptocurrency wallet addresses for sanctions exposure, darknet activity, and illicit fund sources.

:::tip API Reference
Jump directly to the interactive API docs:

- [API reference](/api) — schemas, examples, and playground
- Create: `POST /api/v2/public/verifications/requests/crypto_wallet_screening/`
- Detail: `GET /api/v2/public/verifications/requests/?verification_id={verification_id}`
:::

## Verification Type

```
crypto_wallet_screening
```

## Use Cases

- Crypto exchange compliance
- Wallet sanctions screening
- AML checks for digital asset flows

## Input Parameters

Pass these fields inside `input_data` in your request body.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `email` | string | Yes | Customer's email address. |
| `is_crypto_request` | boolean | Yes | Must be `true` for crypto wallet screening. |
| `verification_mode` | string | Yes | Verification mode. Use `"any"`. |
| `background_checks` | object | Yes | Crypto wallet screening configuration. See nested fields below. |

### `background_checks` object

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | object | Yes | Wallet address details. See nested fields below. |
| `filters` | array of string | No | Screening categories to run. See allowed values below. |

### `background_checks.name` object

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `full_name` | string | Yes | Cryptocurrency wallet address to screen (EVM, Bitcoin, Tron, or Solana). |
| `match_score` | integer | No | Matching threshold from `0` to `100`. A score of `100` applies the strictest accuracy. Defaults to `100`. |

### Allowed `filters` values

| Value | Label |
| --- | --- |
| `sanction` | SANCTION |
| `warning` | WARNING |
| `fitness-probity` | FITNESS PROBITY |
| `SIP` | SIP |
| `SIE` | SIE |
| `Insolvency` | INSOLVENCY |
| `pep` | PEP |
| `pep-class-1` | PEP CLASS 1 |

## Making a Request

Public API creates always use **direct (offsite)** mode. Do not send `method_type` — the API forces `offsite`.

**Endpoint:** `POST https://api.verifyafrica.io/api/v2/public/verifications/requests/crypto_wallet_screening/`

Authenticate with `Authorization: Bearer <VA-…api-key>`. The product path selects the verification type — do not send `verification_type`.

```json
{
  "input_data": {
    "email": "customer@example.com",
    "is_crypto_request": true,
    "verification_mode": "any",
    "background_checks": {
      "name": {
        "full_name": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb",
        "match_score": 100
      },
      "filters": [
        "sanction",
        "warning",
        "fitness-probity",
        "SIP",
        "SIE",
        "Insolvency",
        "pep",
        "pep-class-1"
      ]
    }
  }
}
```

  "message": "Invalid API key.",
  "errors": ["Invalid API key."]
